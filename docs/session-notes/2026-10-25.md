## The expensive wrong turn, and what settled it

Initial testing used `opencode run "/research …"`. Every run returned prose and
ignored the required format. Three rounds of prompt rewording later, the
conclusion "the local model won't follow the format" looked solid — and was
wrong.

What settled it: capturing the actual provider request.

- `opencode run` does **not** expand slash commands. It sends the literal text
  `"/research <question>"`. Captured user message confirmed it; marker commands
  in both `.opencode/command/` and `.opencode/commands/` also arrived verbatim.
- Commands are a **server** concept: `GET /api/command?location[directory]=<dir>`
  listed 34 commands including `research`, and
  `POST /api/session/{id}/command` expanded the template to 1,066 chars with the
  topic substituted.
- Feeding that exact template to the local model produced the answer, a 7-row
  evidence table, a confidence line and `Unverified: none` — the format works.

Method, for reuse: point the provider's `baseURL` at a local logging proxy,
run one command through the API, inspect `messages[]`, restore the config
(trap-protected so a dead proxy cannot be left in place). Read the system
prompt too — it carries the skills catalog and no command catalog, which is why
the model could load the skill from a hint but never saw the template.

Cost: most of the session, plus one wrong commit message (amended in `4be10e5`
so history records the real cause).

**Rule for next time:** slash commands are TUI/API-only. `opencode run` sends
prose, so it cannot test a command. Test commands through the TUI, or through
`POST /api/session/{id}/command`.

### 2. Grind: #451 + #454 (PRs #451 + #456)

Two issues processed through the grind workflow:

**#451 — `check-worktree.sh` primary checkout detection fix** (PR #451, squash
`615cd34`): The script used to derive a "primary path" from the script's own
location and compare it against `git worktree list`, which always matched the
worktree the caller was standing in — so every worktree commit printed "in the
primary checkout", and the genuine case (primary checkout left on a feature
branch) was buried under noise. Fixed by using `git rev-parse --git-common-dir`
vs `--absolute-git-dir` (identical only in the primary checkout). Also fixed the
`GREEN` color variable bug that was hidden by the detection bug. 8 real-repo
tests added. The PR included collateral changes (Caddyfile redirect support, 2
KB articles) merged together per operator preference.

**#454 — 33 dead global skill symlinks** (PR #456, squash `44d20af`): All 45
entries in `~/.config/opencode/skills/` were symlinks; 33 pointed into a deleted
worktree (`opskit-wt-437`), making them dead. Added
`bin/check-global-skills.sh` — a doctor script that reports broken links
(`--check`, exit 1 if found) and repoints them to the main checkout (`--fix`).
The 33 broken symlinks were manually repointed during this session; 0 remain
broken. 4 tests added.
